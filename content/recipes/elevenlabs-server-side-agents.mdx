## Overview

Anam's server-side ElevenLabs integration connects an Anam avatar to an ElevenLabs Conversational AI agent. Your server fetches a short-lived ElevenLabs signed URL and includes it when creating an Anam session token.

The browser uses the Anam JavaScript SDK to start the WebRTC session and render the avatar. Anam sends conversation audio to ElevenLabs, receives the generated speech, and keeps the avatar in sync. API keys and agent IDs stay on the server, the route rejects requests from other sites and limits how many conversations start, and completed sessions include recordings and transcripts in Anam Lab.

The complete example code is available at [examples/elevenlabs-server-side-agent-nextjs](https://github.com/anam-org/anam-cookbook/tree/main/examples/elevenlabs-server-side-agent-nextjs).

## Best practices for configuring ElevenLabs agents

All of this configuration happens in the [ElevenLabs agent dashboard](https://elevenlabs.io/app/agents/agents).

**LLM choice.** Pick a model with low latency and fast throughput — for example we found Qwen3-30B-A3B to be great for low latency. Reasoning models are not recommended unless you're using a high-throughput provider like Groq. If slower LLM responses are a problem, set a soft timeout in the Advanced tab (e.g. 2 seconds) and configure it to either use a fixed filler phrase or generate one with a faster LLM while the main response generates.

**Voices.** For maximum expressivity, use V3 Conversational with Expressive mode enabled. Anam maps supported v3 tags such as `[laughs]`, `[whispers]`, and `[gasps]` to Director Notes, so they affect the avatar's performance as well as the voice. If latency is your highest concern, it's worth trying Flash or another model that is less expressive but faster.

**Background noise.** If background noise is being picked up, turn on the Filter Background Speech toggle in the Advanced menu. It's unclear whether this has an effect on latency.

**User input audio format.** In the Advanced tab, set the user input audio format to **PCM 16000Hz**. Other input formats are not currently supported with Anam.

**Response speed.** For the quickest responses, set Eagerness to Eager in the Advanced menu.

## How it works

The session is split between your Next.js server, the browser, and Anam's engine:

```
Server:
  1. Sign a single-use start ticket (server action)
  2. Check the request's origin, redeem the ticket and
     apply the rate limits
  3. Fetch signed URL from ElevenLabs API
  4. Create Anam session token with Cara-4.1 Express Director Notes
     and elevenLabsAgentSettings

Client:
  5. createClient(sessionToken)
  6. streamToVideoElement("avatar-video")

Engine (automatic):
  7. Connects to ElevenLabs agent via signed URL
  8. User speech → ElevenLabs STT → LLM → TTS → Anam face rendering
  9. Supported v3 tags → Director Notes cues
  10. Avatar video delivered over WebRTC
  11. Client tool calls and results forwarded over the same connection
```

The Next.js route supplies the ElevenLabs settings when it creates the session token. The browser receives that token and uses the Anam JavaScript SDK to start the avatar stream.

## Prerequisites

- Node.js 20.9+
- An [Anam](https://anam.ai) account and API key (sign up free at [lab.anam.ai](https://lab.anam.ai))
- An avatar that supports Cara-4.1 Express, from the Anam Lab Avatars page
- An [ElevenLabs](https://elevenlabs.io) account with a Conversational AI agent configured via the dashboard

## Server-side setup

You need one API route. It checks that the request came from your own site, fetches a signed URL from ElevenLabs, then passes it to Anam when creating a session token.

API keys and IDs stay server-side. The route reads the avatar ID (which face to render) and the ElevenLabs agent ID from environment variables, so a caller can't point your keys at a different agent or avatar.

### Environment variables

```bash
ANAM_API_KEY=your_anam_api_key
ELEVENLABS_API_KEY=your_elevenlabs_api_key
ANAM_AVATAR_ID=your_avatar_id
ELEVENLABS_AGENT_ID=your_elevenlabs_agent_id
# 32+ random characters. Generate one with:
# node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
SESSION_SECRET=your_random_secret
# Your public origin. Optional locally; set it in production
# APP_ORIGIN=https://example.com
```

None of these use the `NEXT_PUBLIC_` prefix, so Next.js never sends them to the browser.

### Protect the route

Every session uses minutes on your Anam account and your ElevenLabs agent. Without a check, any website or script could call the route and start sessions on your keys. The route makes three checks:

- **Same origin.** The route rejects requests that a browser sent from another site.
- **Start ticket.** Just before each start, a server action signs a ticket with `SESSION_SECRET`, which never leaves the server. The route accepts each ticket once, within two minutes.
- **Rate limits.** The route caps starts per visitor and for the whole site.

The first two stop other websites from using your route from a visitor's browser. They aren't user authentication: a script can still ask the server action for a ticket, which is why the rate limits are there too. In a real app, also check your own user session in the route and rate-limit per user.

Set `APP_ORIGIN` in production. Without it, the expected origin comes from the request's own `Host` header, so any hostname that points at your server passes the check.

The `server-only` import makes the build fail if a client component imports the file, so `SESSION_SECRET` can't end up in the browser bundle.

```typescript
// lib/session-auth.ts
// Server only: the build fails if a client component imports this file.
import "server-only";
import { createHmac, randomBytes, timingSafeEqual } from "node:crypto";

const TICKET_TTL_MS = 2 * 60 * 1000;

// Redeemed ticket nonces, so each ticket starts one conversation. The map
// lives in memory, so it resets on restart and isn't shared between server
// instances. Keep it in Redis or your database if you run several instances.
const redeemed = new Map<string, number>();

function secret() {
  const value = process.env.SESSION_SECRET;
  if (!value || value.length < 32) {
    throw new Error("SESSION_SECRET must be set to at least 32 characters");
  }
  return value;
}

function sign(payload: string) {
  return createHmac("sha256", secret()).update(payload).digest("base64url");
}

/** Signs a ticket that lets the browser start one conversation. */
export function createStartTicket(now = Date.now()) {
  const payload = `${now + TICKET_TTL_MS}.${randomBytes(16).toString("base64url")}`;
  return `${payload}.${sign(payload)}`;
}

/** Checks a ticket's signature and expiry, and accepts each ticket once. */
export function redeemStartTicket(ticket: unknown, now = Date.now()) {
  if (typeof ticket !== "string" || ticket.length > 200) return false;

  const [expiresAt, nonce, signature, ...rest] = ticket.split(".");
  if (!expiresAt || !nonce || !signature || rest.length > 0) return false;

  const expected = Buffer.from(sign(`${expiresAt}.${nonce}`));
  const actual = Buffer.from(signature);
  if (actual.length !== expected.length || !timingSafeEqual(actual, expected)) {
    return false;
  }

  const expiry = Number(expiresAt);
  if (!Number.isSafeInteger(expiry) || expiry <= now) return false;

  for (const [key, keyExpiry] of redeemed) {
    if (keyExpiry <= now) redeemed.delete(key);
  }
  if (redeemed.has(nonce)) return false;
  redeemed.set(nonce, expiry);
  return true;
}

/**
 * Accepts only requests sent by a page on this site. Browsers always send
 * Origin on a POST from fetch(), and other sites can't change it.
 */
export function isSameOrigin(request: Request, appOrigin: string | null) {
  const fetchSite = request.headers.get("sec-fetch-site");
  if (fetchSite && fetchSite !== "same-origin") return false;

  const origin = request.headers.get("origin");
  return origin !== null && origin === (appOrigin ?? originFromHost(request));
}

// Without APP_ORIGIN, the expected origin comes from the request's own Host
// header, so any hostname that reaches the server passes. That's fine for
// local development. In production, set APP_ORIGIN to your public origin.
function originFromHost(request: Request) {
  const host = request.headers.get("host");
  if (!host) return null;
  const protocol =
    request.headers.get("x-forwarded-proto")?.split(",")[0].trim() ||
    new URL(request.url).protocol.replace(":", "");
  return `${protocol}://${host}`;
}

const REQUIRED_SETTINGS = [
  "ANAM_API_KEY",
  "ELEVENLABS_API_KEY",
  "ANAM_AVATAR_ID",
  "ELEVENLABS_AGENT_ID",
  "SESSION_SECRET",
];

/**
 * Reads the server-only settings. Returns null, and logs why, if any are
 * missing or invalid.
 */
export function readServerConfig() {
  const env = process.env;
  const missing = REQUIRED_SETTINGS.filter((name) => !env[name]);
  if (missing.length > 0) {
    console.error(`Missing settings: ${missing.join(", ")}. See .env.example.`);
    return null;
  }
  if (env.SESSION_SECRET!.length < 32) {
    console.error("SESSION_SECRET must be at least 32 characters.");
    return null;
  }
  if (env.APP_ORIGIN && !isOrigin(env.APP_ORIGIN)) {
    console.error("APP_ORIGIN must be an origin such as https://example.com.");
    return null;
  }

  return {
    anamApiKey: env.ANAM_API_KEY!,
    elevenLabsApiKey: env.ELEVENLABS_API_KEY!,
    avatarId: env.ANAM_AVATAR_ID!,
    agentId: env.ELEVENLABS_AGENT_ID!,
    appOrigin: env.APP_ORIGIN ? new URL(env.APP_ORIGIN).origin : null,
  };
}

// True for a bare http(s) origin such as https://example.com, with no path.
function isOrigin(value: string) {
  try {
    const url = new URL(value);
    return (
      (url.protocol === "https:" || url.protocol === "http:") &&
      value.replace(/\/$/, "") === url.origin
    );
  } catch {
    return false;
  }
}
```

### Rate limits

The ticket check doesn't stop a script that asks for a fresh ticket each time, so the route also caps conversation starts. A visitor is an ID in an httpOnly cookie. A script can drop the cookie, so the site-wide daily cap is what bounds your spend:

```typescript
// lib/rate-limit.ts
// Caps conversation starts per visitor and for the whole site. Every session
// uses minutes on your Anam account and your ElevenLabs agent, and the start
// ticket doesn't stop a script that asks for a fresh ticket each time.
//
// The counts live in memory, so they reset when the server restarts and
// aren't shared between instances. In production, keep them in Redis or your
// database and update them atomically. Tune the limits to your traffic.

import "server-only";

type Window = { limit: number; ms: number };

const MINUTE = 60_000;
const DAY = 24 * 60 * MINUTE;

const PER_VISITOR: Window[] = [
  { limit: 6, ms: 10 * MINUTE },
  { limit: 30, ms: DAY },
];
const SITE_PER_DAY: Window[] = [{ limit: 500, ms: DAY }];

const counts = new Map<string, { count: number; expires: number }>();

export type Verdict = { ok: true } | { ok: false; retryAfterSeconds: number };

/**
 * Checks every window before counting anything, so a refused start stores
 * nothing and doesn't use up another window. Only accepted starts are
 * stored, so the site's daily cap also caps the size of the map.
 */
export function takeStartSlot(visitorId: string, now = Date.now()): Verdict {
  const windows = [
    ...PER_VISITOR.map((window) => ({ ...window, key: `visitor:${visitorId}` })),
    ...SITE_PER_DAY.map((window) => ({ ...window, key: "site" })),
  ].map(({ key, limit, ms }) => {
    const start = Math.floor(now / ms) * ms;
    const id = `${key}:${ms}:${start}`;
    return { id, limit, expires: start + ms, count: counts.get(id)?.count ?? 0 };
  });
  const full = windows.find((window) => window.count >= window.limit);
  if (full) {
    return { ok: false, retryAfterSeconds: Math.ceil((full.expires - now) / 1000) };
  }

  for (const [id, entry] of counts) if (entry.expires <= now) counts.delete(id);
  for (const window of windows) {
    counts.set(window.id, { count: window.count + 1, expires: window.expires });
  }
  return { ok: true };
}
```

Used tickets and these counts live in memory. If you run several instances, keep the counts in Redis or your database so the limits hold across instances.

### API route

```typescript
// app/api/anam-session/route.ts
import { randomUUID } from "node:crypto";
import { cookies } from "next/headers";
import { NextResponse } from "next/server";
import { takeStartSlot } from "@/lib/rate-limit";
import {
  isSameOrigin,
  readServerConfig,
  redeemStartTicket,
} from "@/lib/session-auth";

/**
 * Creates an Anam session token with ElevenLabs agent settings.
 *
 * Fetches the ElevenLabs signed URL server-side, then passes it to
 * the Anam session token API via environment.elevenLabsAgentSettings.
 * Anam handles the ElevenLabs connection, while the client only
 * streams the avatar.
 *
 * The avatar and agent IDs come from server environment variables, not
 * from the request, so a caller can't point your API keys at other agents.
 */
export async function POST(request: Request) {
  const config = readServerConfig();
  if (!config) {
    return NextResponse.json(
      { error: "The server settings are missing or invalid. See .env.example." },
      { status: 500 }
    );
  }

  if (!isSameOrigin(request, config.appOrigin)) {
    return NextResponse.json(
      { error: "Start the conversation from this site." },
      { status: 403 }
    );
  }

  const body = await request.json().catch(() => null);
  if (!redeemStartTicket(body?.ticket)) {
    return NextResponse.json(
      { error: "Couldn't verify this request. Try again." },
      { status: 401 }
    );
  }

  // A visitor is an ID in an httpOnly cookie. A script that drops the cookie
  // gets a new ID each time, so the site-wide cap is what bounds your spend.
  const jar = await cookies();
  let visitorId = jar.get("visitor")?.value;
  if (!visitorId) {
    visitorId = randomUUID();
    jar.set("visitor", visitorId, {
      httpOnly: true,
      sameSite: "lax",
      secure: process.env.NODE_ENV === "production",
      path: "/",
      maxAge: 60 * 60 * 24 * 365,
    });
  }
  const verdict = takeStartSlot(visitorId);
  if (!verdict.ok) {
    // A wait of more than 10 minutes means a daily limit is full.
    const error =
      verdict.retryAfterSeconds > 600
        ? "This demo has reached its conversation limit for today."
        : "Please wait a few minutes before starting another conversation.";
    return NextResponse.json(
      { error },
      {
        status: 429,
        headers: { "Retry-After": String(verdict.retryAfterSeconds) },
      }
    );
  }

  try {
    // Fetch the ElevenLabs signed URL.
    const elRes = await fetch(
      `https://api.elevenlabs.io/v1/convai/conversation/get-signed-url?agent_id=${encodeURIComponent(config.agentId)}`,
      {
        headers: { "xi-api-key": config.elevenLabsApiKey },
        cache: "no-store",
        signal: AbortSignal.timeout(15_000),
      }
    );

    if (!elRes.ok) {
      console.error("ElevenLabs API error:", elRes.status, await elRes.text());
      return NextResponse.json(
        { error: "Couldn't connect to the ElevenLabs agent." },
        { status: 502 }
      );
    }

    const { signed_url: signedUrl } = await elRes.json();

    // Create an Anam session token with the ElevenLabs agent settings.
    const sessionTokenBody = {
      // The token can start one session (the SDK retries up to 3 times) and
      // expires after 5 minutes, so a copied token is of little use.
      maxSessions: 3,
      expiresInSeconds: 300,
      personaConfig: {
        avatarId: config.avatarId,
        avatarModel: "cara-4.1-express",
        directorNotes: {
          presetStyle: "warm",
          expressivity: 0.5,
        },
      },
      environment: {
        elevenLabsAgentSettings: {
          signedUrl,
          agentId: config.agentId,
        },
      },
    };
    const anamRes = await fetch("https://api.anam.ai/v1/auth/session-token", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${config.anamApiKey}`,
      },
      body: JSON.stringify(sessionTokenBody),
      cache: "no-store",
      signal: AbortSignal.timeout(15_000),
    });

    if (!anamRes.ok) {
      console.error("Anam API error:", anamRes.status, await anamRes.text());
      return NextResponse.json(
        { error: "Couldn't create the Anam session." },
        { status: 502 }
      );
    }

    const data = await anamRes.json();
    return NextResponse.json({ sessionToken: data.sessionToken });
  } catch (error) {
    console.error("Session setup failed:", error);
    return NextResponse.json(
      { error: "Couldn't start the session. Try again." },
      { status: 502 }
    );
  }
}
```

The `environment.elevenLabsAgentSettings` field configures ElevenLabs as the session's speech recognition, language model, and text-to-speech provider. `avatarModel` and `directorNotes` enable a warm Cara-4.1 Express performance at the start of the session.

<Info>
The signed URL is short-lived (typically valid for 15 minutes). Anam uses it immediately when the client connects, so there's no issue with expiry in normal usage. If you're pre-fetching tokens, create them just before the client needs them.
</Info>

## Director Notes with ElevenLabs v3

Director Notes give the avatar a baseline performance style and temporary expression cues. The server route above starts with the `warm` preset at `0.5` expressivity. Expressivity accepts values from `0` to `1`; higher values strengthen both the active style and speech-driven motion.

<Warning>
Director Notes only work with Cara 4 avatars. Use an avatar ID that supports Cara-4.1 Express and set `avatarModel` to `"cara-4.1-express"`, as shown in the server route above.
</Warning>

Select **V3 Conversational** in the ElevenLabs Agent Voice settings. Expressive mode is enabled automatically for that model. Then add a short rule to the agent's system prompt:

```text
Use ElevenLabs v3 expressive tags sparingly when the delivery should change.
For testing, use tags such as [excited], [laughs], [whispers], [sighs],
[gasps], [angrily], [sarcastic], or [nervous].
Place each tag immediately before the words it should affect.
Do not explain or read the tags aloud.
```

The [ElevenLabs Expressive mode guide](https://elevenlabs.io/docs/eleven-agents/customization/voice/expressive-mode) explains how v3 tags affect the voice. For this integration, Anam recognizes the following provider tags and maps each group to one Director Note cue:

| Director Note cue | Recognized ElevenLabs v3 tags |
|---|---|
| `happy` | `[excited]`, `[happily]`, `[cheerfully]`, `[elated]` |
| `laughter` | `[laugh]`, `[laughs]`, `[laughing]`, `[laughs harder]`, `[starts laughing]`, `[chuckles]`, `[chuckling]`, `[giggles]`, `[giggling]` |
| `warm` | `[whispers]`, `[whispering]`, `[quietly]` |
| `playful` | `[sarcastic]`, `[playfully]` |
| `curious` | `[curiously]`, `[quizzical]`, `[quizzically]` |
| `concerned` | `[sigh]`, `[sighs]`, `[exhales]` |
| `sad` | `[sadly]`, `[sorrowful]`, `[tearful]`, `[crying]` |
| `surprised` | `[gasp]`, `[gasps]`, `[startled]` |
| `angry` | `[angrily]`, `[furious]`, `[intensely]` |
| `distressed` | `[nervous]`, `[fearful]`, `[scared]` |

This table is the complete alias list that Anam recognizes. ElevenLabs supports other audio tags, but Anam does not map them to Director Notes. A recognized tag is removed from the transcript before it reaches the browser. An unknown bracketed tag remains ordinary transcript text.

The example listens for `DIRECTOR_NOTE_CUE_APPLIED` so you can see whether the engine recognized and applied a tag:

```typescript
const [directorNoteActivity, setDirectorNoteActivity] = useState<{
  cueTag: string;
  correlationId: string;
} | null>(null);

anamClient.addListener(AnamEvent.DIRECTOR_NOTE_CUE_APPLIED, (evt) => {
  setDirectorNoteActivity({
    cueTag: evt.cueTag,
    correlationId: evt.correlationId,
  });
});
```

The event contains the normalized Anam cue. For example, ElevenLabs `[laughs]` produces a `laughter` cue, while `[whispers]` produces `warm`. The [Anam Director Notes guide](https://anam.ai/docs/personas/director-notes) covers baseline styles, expressivity, cue events, and Cara 4 requirements.

## Per-session customisation

The Anam session token API accepts additional fields that are passed through to ElevenLabs when starting the conversation. These let you personalise each session — greet users by name, switch languages, override the system prompt, or pass data to a custom LLM backend. See the [ElevenLabs personalisation overview](https://elevenlabs.io/docs/eleven-agents/customization/personalization) for full details.

All of these fields are optional. Add them to `elevenLabsAgentSettings` in the route's `sessionTokenBody`, next to `signedUrl` and `agentId`:

```typescript
elevenLabsAgentSettings: {
  signedUrl,
  agentId: config.agentId,
  dynamicVariables: { ... },          // optional
  conversationConfigOverride: { ... }, // optional
  userId: "...",                       // optional
  customLlmExtraBody: { ... },        // optional
},
```

The snippets below show only the field to add.

### Dynamic variables

Dynamic variables are the simplest way to personalise a conversation at runtime. Define placeholders like `{{user_name}}` in your agent's system prompt or first message in the ElevenLabs dashboard, then fill them in when creating the session token:

```typescript
dynamicVariables: {
  user_name: "Alice",
  account_type: "premium",
},
```

See [ElevenLabs dynamic variables docs](https://elevenlabs.io/docs/eleven-agents/customization/personalization/dynamic-variables) for the full syntax.

### Overrides

Overrides let you change agent behaviour per conversation — things like the first message, language, system prompt, or TTS voice. Only include the fields you want to override; everything else keeps its default from the ElevenLabs dashboard.

```typescript
conversationConfigOverride: {
  agent: {
    prompt: {
      prompt: "You are a helpful assistant. Always respond in Spanish.",
    },
    firstMessage: "¡Hola! ¿En qué puedo ayudarte hoy?",
    language: "es",
  },
},
```

See [ElevenLabs overrides docs](https://elevenlabs.io/docs/eleven-agents/customization/personalization/overrides) for the full list of overridable fields.

### User ID

Pass `userId` to identify the caller in ElevenLabs analytics and conversation history. Take it from your own user session on the server, not from the request body:

```typescript
userId: "user_abc123",
```

### Custom LLM extra body

If your ElevenLabs agent is configured to call a custom LLM backend, `customLlmExtraBody` lets you pass arbitrary parameters alongside each request:

```typescript
customLlmExtraBody: {
  session_context: { region: "eu", tier: "enterprise" },
},
```

See [ElevenLabs custom LLM docs](https://elevenlabs.io/docs/eleven-agents/customization/llm/custom-llm) for how to set up a custom LLM backend.

## Start the avatar session

Add a server action that signs a start ticket. The browser calls it just before each start, so the ticket is always fresh. Next.js rejects server actions from other sites' pages, but a script that sends no `Origin` header still gets a ticket, so treat the ticket as a cross-site deterrent rather than authentication:

```typescript
// app/actions.ts
"use server";

import { createStartTicket, readServerConfig } from "@/lib/session-auth";

/**
 * Signs a start ticket just before the browser calls /api/anam-session.
 *
 * Next.js rejects a server action whose Origin header names another host, so
 * other websites can't get tickets from their visitors' browsers. A request
 * with no Origin header, such as one from a script, still gets a ticket. The
 * ticket deters cross-site use; it isn't authentication, which is why the
 * route also rate-limits starts.
 */
export async function getStartTicket() {
  return readServerConfig() ? createStartTicket() : null;
}
```

In the browser, get a ticket, send it to your route, create an Anam client with the session token, and attach its stream to your video element:

```typescript
import { createClient } from "@anam-ai/js-sdk";
import { getStartTicket } from "./actions";

const ticket = await getStartTicket();
if (!ticket) throw new Error("The server settings are missing or invalid");

const res = await fetch("/api/anam-session", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ ticket }),
});
const body = await res.json().catch(() => ({}));
if (!res.ok) throw new Error(body.error ?? "Failed to create a session token");

const client = createClient(body.sessionToken);
await client.streamToVideoElement("avatar-video");
```

`streamToVideoElement()` starts microphone capture and renders the avatar's video and audio in the element with the matching ID.

### Working component example

Below is a React component with connection lifecycle and a streaming transcript. Render it from any page, such as `app/page.tsx`.

The `MESSAGE_STREAM_EVENT_RECEIVED` event fires for each chunk of text from both the user and the agent. Accumulate chunks by message ID to build the full transcript.

The component also cleans up after itself. When the session ends, the connection closes, or the component unmounts, it removes its event listeners and calls `stopStreaming()`, so the session and the microphone don't outlive the page. If it unmounts while still connecting, it ends the new session as soon as it opens.

```typescript
// app/AvatarChat.tsx
"use client";

import { useCallback, useEffect, useRef, useState } from "react";
import {
  AnamEvent,
  ConnectionClosedCode,
  createClient,
  type AnamClient,
} from "@anam-ai/js-sdk";
import { getStartTicket } from "./actions";

type Message = {
  id: string;
  role: "user" | "persona";
  content: string;
  interrupted?: boolean;
};

export default function AvatarChat() {
  const clientRef = useRef<AnamClient | null>(null);
  // Undo functions for the session's microphone and event listeners
  const cleanupRef = useRef<Array<() => void>>([]);
  // Bumped on every teardown, so a start() still in progress gives up
  const attemptRef = useRef(0);
  const abortRef = useRef<AbortController | null>(null);
  const [status, setStatus] = useState<"idle" | "connecting" | "connected">("idle");
  const [messages, setMessages] = useState<Message[]>([]);
  const [error, setError] = useState<string | null>(null);

  // Remove the listeners, end the session, and cancel a start in progress
  const release = useCallback(() => {
    attemptRef.current += 1;
    abortRef.current?.abort();
    abortRef.current = null;
    cleanupRef.current.forEach((cleanup) => cleanup());
    cleanupRef.current = [];
    const client = clientRef.current;
    clientRef.current = null;
    void client?.stopStreaming().catch(() => {});
  }, []);

  // End the session and release the microphone when the component unmounts
  useEffect(() => release, [release]);

  const start = useCallback(async () => {
    release();
    const attempt = attemptRef.current;
    const abortController = new AbortController();
    abortRef.current = abortController;
    // Kept outside the try, so the catch can end a session that failed
    // after Stop or unmount
    let startedClient: AnamClient | null = null;
    setStatus("connecting");
    setMessages([]);
    setError(null);

    try {
      // Ask for the microphone here, so a permission grant that arrives
      // after Stop or unmount can still be released
      const micStream = await navigator.mediaDevices.getUserMedia({
        audio: { echoCancellation: true },
      });
      const stopMic = () => micStream.getTracks().forEach((t) => t.stop());
      if (attempt !== attemptRef.current) return stopMic();
      cleanupRef.current.push(stopMic);

      // Get a fresh, single-use ticket from the server action
      const ticket = await getStartTicket();
      if (attempt !== attemptRef.current) return;
      if (!ticket) throw new Error("The server settings are missing or invalid");

      // Aborted if the user stops or the component unmounts first
      const res = await fetch("/api/anam-session", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ ticket }),
        signal: abortController.signal,
      });
      const body = await res.json().catch(() => ({}));
      if (attempt !== attemptRef.current) return;
      if (!res.ok) {
        throw new Error(body.error ?? "Failed to create a session token");
      }

      const anamClient = createClient(body.sessionToken);
      startedClient = anamClient;
      clientRef.current = anamClient;

      // Accumulate transcript chunks by message ID
      const onMessage = (evt: {
        id: string;
        content: string;
        role: string;
        interrupted: boolean;
      }) => {
        setMessages((prev) => {
          const idx = prev.findIndex((m) => m.id === evt.id);
          if (idx >= 0) {
            const next = [...prev];
            next[idx] = {
              ...next[idx],
              content: next[idx].content + evt.content,
              interrupted: evt.interrupted,
            };
            return next;
          }
          return [
            ...prev,
            {
              id: evt.id,
              role: evt.role as "user" | "persona",
              content: evt.content,
              interrupted: evt.interrupted,
            },
          ];
        });
      };

      // streamToVideoElement() resolves once signalling starts; the session
      // is connected when WebRTC is
      const onConnected = () => setStatus("connected");

      const onClosed = (reason: ConnectionClosedCode, details?: string) => {
        if (clientRef.current !== anamClient) return;
        // Some failures close the connection but keep the microphone open,
        // so always stop the client
        release();
        if (reason !== ConnectionClosedCode.NORMAL) {
          setError(details || `The session ended unexpectedly (${reason})`);
        }
        setStatus("idle");
      };

      anamClient.addListener(AnamEvent.MESSAGE_STREAM_EVENT_RECEIVED, onMessage);
      anamClient.addListener(AnamEvent.CONNECTION_ESTABLISHED, onConnected);
      anamClient.addListener(AnamEvent.CONNECTION_CLOSED, onClosed);
      cleanupRef.current.push(
        () => anamClient.removeListener(AnamEvent.MESSAGE_STREAM_EVENT_RECEIVED, onMessage),
        () => anamClient.removeListener(AnamEvent.CONNECTION_ESTABLISHED, onConnected),
        () => anamClient.removeListener(AnamEvent.CONNECTION_CLOSED, onClosed)
      );

      await anamClient.streamToVideoElement("avatar-video", micStream);
      if (attempt !== attemptRef.current) {
        // Stopped or unmounted while connecting: end the new session
        void anamClient.stopStreaming().catch(() => {});
      }
    } catch (error) {
      if (attempt !== attemptRef.current) {
        // Stopped or unmounted, then the start failed: end the session too,
        // so the server doesn't wait for it to time out
        void startedClient?.stopStreaming().catch(() => {});
        return;
      }
      console.error("Failed to start the avatar session:", error);
      release();
      setError(error instanceof Error ? error.message : "Failed to start");
      setStatus("idle");
    }
  }, [release]);

  const stop = useCallback(() => {
    release();
    setStatus("idle");
  }, [release]);

  return (
    <div>
      <video id="avatar-video" autoPlay playsInline />
      {/* Stop also cancels a start that hangs, such as a pending mic prompt */}
      <button onClick={status === "idle" ? start : stop}>
        {status === "idle" ? "Start" : status === "connecting" ? "Cancel" : "Stop"}
      </button>
      {error && <p role="alert">{error}</p>}
      <ul>
        {messages.map((message) => (
          <li key={message.id}>
            <strong>{message.role === "user" ? "You" : "Agent"}:</strong>{" "}
            {message.content}
            {message.interrupted && " (interrupted)"}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

For more on event handling, message history, and connection lifecycle, see the [basic Next.js app recipe](/cookbook/basic-nextjs-app).

## Add a client tool

This example includes an ElevenLabs client tool named `show_notification`. When the agent calls it, Anam forwards the call to the JavaScript SDK in the browser. The handler displays the requested message and returns a result to the ElevenLabs conversation.

### Configure the tool in ElevenLabs

In the ElevenLabs agent dashboard, open **Tools** and add the following tool:

| Setting | Value |
|---|---|
| Tool Type | **Client** |
| Name | `show_notification` |
| Wait for response | Enabled |
| Required parameter | `message` (String) |

Tool and parameter names are case-sensitive. Describe the tool as displaying a message on screen when the user asks for one. The [ElevenLabs client tools guide](https://elevenlabs.io/docs/eleven-agents/customization/tools/client-tools) shows where to find these settings.

### Register the handler

Register the handler before starting the Anam stream:

```typescript
const unregisterToolHandlers = [
  anamClient.registerToolCallHandler("show_notification", {
    onStart: async ({ arguments: args }) => {
      if (typeof args.message !== "string" || !args.message.trim()) {
        throw new Error("message must be a non-empty string");
      }

      const message = args.message.trim();
      setNotification(message);
      return `Displayed the notification: ${message}`;
    },
    onFail: async ({ errorMessage }) => {
      console.error("show_notification failed:", errorMessage);
    },
  }),
];

await anamClient.streamToVideoElement("avatar-video");
```

Returning a string from `onStart` sends that value back as the tool result. With **Wait for response** enabled, ElevenLabs adds it to the conversation context before the agent continues. Keep the functions in `unregisterToolHandlers` and call them when the session ends or the component unmounts. The [Anam client tools docs](https://anam.ai/docs/personas/tools/client-tools) cover the full handler lifecycle.

The [complete example](https://github.com/anam-org/anam-cookbook/tree/main/examples/elevenlabs-server-side-agent-nextjs) includes argument validation, a notification UI, handler cleanup, and a status panel for checking tool calls.

## Troubleshooting

**"Start the conversation from this site." (403)**
- The route only accepts browser requests from a page on the same origin, including the scheme and port. Call it from your own site
- If a proxy in front of your app changes the `Host` header, set `APP_ORIGIN` to your public origin, such as `https://example.com`

**The server action fails before it runs, behind a proxy**
- If the proxy rewrites `Host` and doesn't forward the public host in `X-Forwarded-Host`, Next.js rejects the server action. Add your public host to [`serverActions.allowedOrigins`](https://nextjs.org/docs/app/api-reference/config/next-config-js/serverActions#allowedorigins) and set `APP_ORIGIN`

**"The server settings are missing or invalid." (500)**
- The server log names the missing or invalid setting
- `SESSION_SECRET` must be at least 32 characters
- `APP_ORIGIN` must be an origin such as `https://example.com`, with the scheme and no path

**"Please wait a few minutes before starting another conversation." (429)**
- The visitor or the site reached a rate limit in `lib/rate-limit.ts`. Raise the limits to suit your traffic

**"Couldn't verify this request. Try again." (401)**
- Each start gets a new ticket that works once, within two minutes. Click Start again
- Check that `SESSION_SECRET` is set, at least 32 characters, and the same on every server instance
- If you run several instances, keep redeemed tickets in a shared store such as Redis

**"Couldn't connect to the ElevenLabs agent."**
- Check the server logs for the ElevenLabs status code
- Verify `ELEVENLABS_API_KEY` is set and valid
- Confirm `ELEVENLABS_AGENT_ID` matches an agent in your ElevenLabs dashboard
- Check that your ElevenLabs plan includes Conversational AI access

**Avatar connects but no conversation starts**
- The signed URL may have expired. Create the session token right before the client needs it, not minutes in advance
- Verify the ElevenLabs agent is active and not paused in the dashboard

**Director Notes status stays "waiting"**
- Confirm the avatar supports Cara-4.1 Express and `avatarModel` is set to `cara-4.1-express`
- Select V3 Conversational in ElevenLabs and prompt the agent to emit one of the recognized tags listed above
- Check the response transcript in ElevenLabs to confirm the LLM produced the tag
- Confirm the Anam engine build includes the ElevenLabs Director Notes aliases

**Client tool status stays "ready"**
- Confirm the tool type is **Client** in ElevenLabs
- Match the registered tool and parameter names exactly; they are case-sensitive
- Enable **Wait for response** if the agent needs to receive the handler's returned string

**"Couldn't create the Anam session."**
- Check the server logs for the Anam status code
- Check that `ANAM_AVATAR_ID` is valid. Find available avatars at [lab.anam.ai/avatars](https://lab.anam.ai/avatars)
- Make sure the `elevenLabsAgentSettings` object includes both `signedUrl` and `agentId`

**Avatar lips not syncing / no audio**
- This integration handles audio format matching automatically. If you hit this, check the ElevenLabs agent configuration and make sure it's using a supported voice model

**Session recordings not appearing in Anam Lab**
- Recordings are generated after the session ends. Allow a few minutes for processing
- Check the session completed cleanly (the client called `stopStreaming()` or the connection closed normally)
